prompt-git（Prompt 版本控制与自动评估工具）
痛点：团队 Prompt 散落在代码/文档/聊天记录中，改完不知道效果是否退化；没有版本回溯、对比、自动化评估机制。
核心功能：
CLI 管理 Prompt 模板（prompt-git add/commit/diff/rollback）
自动将 Prompt 变更与历史数据集跑对比评测（准确率/一致性/Token消耗）
生成 CHANGELOG.md + 可视化 diff 报告
支持接入 OpenAI/Anthropic/本地模型做基线对比
技术栈：Python + Typer + SQLite + GitPython + LiteLLM + Pytest + GitHub Actions

为什么耗 Token 且出活快：
Prompt 模板解析、diff 算法、评测 pipeline 均可让 AI 生成骨架
自动生成多组测试用例、评估脚本、CI 流程
迭代 Prompt 本身就会消耗大量 token（调试/对比/优化）


Langfuse 确实覆盖了 Prompt 管理，但它的核心定位与 prompt-git 有本质差异。用一句话概括：
Langfuse 是“运行时观测平台”，prompt-git 是“开发时版本控制工具”。
就像 Datadog 和 Git 的区别：一个盯线上，一个管开发流程。
下面从架构、工作流、场景和简历价值四个维度拆解：
📊 核心差异对比
维度
Langfuse
prompt-git（建议定位）

核心范式
langfuse:SaaS/自托管观测平台（Web UI + 数据库）
prompt-git:本地 CLI 工具（Git 原生 + 文本文件）

存储方式
langfuse:Postgres 集中存储，版本靠数据库记录
prompt-git:Git 仓库管理，Prompt 即代码（YAML/JSON/MD）

工作流重心
langfuse:运行时埋点、追踪、成本监控、团队协作文档
prompt-git:开发时提交、语义 Diff、CI 自动评测、PR 审查

集成方式
langfuse:需侵入代码装 SDK（langfuse.init()）
prompt-git:零侵入，走 pre-commit / GitHub Actions

典型用户
langfuse:ML 工程团队、产品经理、运维
prompt-git:独立开发者、DevOps、追求工程化的小团队

部署成本
langfuse:需起服务、配 DB、维护权限
prompt-git:pip install 或单二进制，CI 内直接跑

💡 为什么 prompt-git 仍有不可替代的价值？
Git 原生工作流缺失
Langfuse 的 Prompt 版本管理是“平台内操作”，无法与 git branch、git merge、git bisect 联动。开发者希望像管代码一样管 Prompt：feature/prompt-v2 → PR → 自动评测 → Merge。

语义 Diff 是硬需求
文本 Diff 对 Prompt 意义有限（改个换行符就全飘红）。prompt-git 可做 结构化/语义 Diff：识别变量替换、意图偏移、约束条件增删，并生成人类可读的 Prompt 变更摘要。这是 Langfuse UI 不提供的。

CI 防退化（Guardrails for Prompts）
在 PR 阶段自动跑历史数据集评测，若准确率/一致性下降 >5% 则 Block Merge。Langfuse 偏向“事后看报表”，而 prompt-git 做“事前拦截”，更贴近现代软件工程的 Quality Gate 理念。

零基础设施，适合个人/快速迭代
你时间紧，Langfuse 需要起服务、配 DB、调 UI。prompt-git 纯 CLI，输出 Markdown/JSON 报告，天然适合 GitHub 开源和 CI 流水线，冷启动成本极低。

prompt-git diff
结构化解析 Prompt，输出变量变更、意图偏移、约束增删的语义 Diff 报告
AI 可生成 AST 解析逻辑、Diff 算法、多格式输出模板；需大量边界用例测试

prompt-git eval
读取本地 datasets/*.jsonl，跑基线对比，输出准确率/一致性/Token 消耗变化
AI 生成评测脚本、指标计算、阈值拦截逻辑；可批量生成测试数据集

prompt-git ci
自动生成 GitHub Action，PR 时自动跑 diff + eval，失败则 Comment 警告
AI 生成 YAML、Webhook 逻辑、Markdown 报告渲染；直接对接 CI/CD
刻意不做的：Web UI、实时追踪、成本计费、团队协作权限。这些是 Langfuse 的腹地，做不过也消耗时间。
